CTR & Engagement Opportunity Scoring for Search Discoverability

Author: Ayush Narkhede  ·  CTR / Engagement Opportunity Scoring  ·  FlyRank ML Internship Capstone  ·  Repository

Abstract

Question. Among pages that already attract search impressions, which ones under-capture clicks relative to peers, and can a model rank them for editorial review better than a simple rule? Method. Using the FlyRank internship warehouse, we built a binary opportunity label from June 2026 GSC outcomes (high impressions, below-median CTR) and features from May 2026 performance plus static content attributes only—strictly sequential windows to avoid leakage. Validation. Models were evaluated with a client-level holdout so no test client appears in training; a rule baseline used the same split. Result. Gradient Boosting achieved ROC-AUC 0.781 versus a rule baseline of 0.577 (test base rate ≈ 22.6%). Use. The ranked output is a decision-support review queue with reason codes—not a causal traffic forecast or auto-publish system.

1. Introduction / Problem statement

Editorial time is scarce. Many pages receive impressions but convert poorly to clicks. Ranking those pages for human review—title, meta, or content checks—is more useful than a global “optimize everything” list.

This work supports that decision: given last month’s visible performance and static content signals, which pages should an editor open first this month? The answer is a ranked queue with explicit limits, not a promise that any rewrite will raise traffic.

2. Data

Source: FlyRank Internship Warehouse (gated public-safe release on Hugging Face).

  • fact_content_daily_performance — aggregated to content × month for May 2026 (features) and June 2026 (label window).
  • dim_content — static attributes (length, search volume, competition, backlinks, URL structure counts).

Excluded (and why):

  • Client names, domains, and raw query strings — public-safety and privacy.
  • June performance fields from the feature matrix — would leak the label window.
  • AI-referral session counts as a primary label — too sparse for a stable binary target; treated as exploratory only.
  • Very low-impression rows — opportunity scoring targets pages that are already visible.

Train rows ≈ 28.5k · Test rows ≈ 9.4k after client holdout. Exact warehouse size is large (tens of millions of daily rows); this study uses monthly aggregates for the windows above.

3. Methodology

3.1 Label

Among pages with sufficient June impressions, label = 1 if CTR is below the high-impression median (opportunity / under-capture), else 0. Base rate on the held-out clients ≈ 22.6%.

3.2 Features

May aggregates only: impressions, clicks, CTR, average position; plus static dim_content fields (keyword/URL length, search volume, competition, CPC, backlinks, category count, body length). No June metrics in X.

3.3 Models & baseline

  • Baseline: rank by inverse May CTR among high-impression pages (simple “already weak CTR” rule).
  • Models: Logistic Regression, Random Forest, Gradient Boosting (scikit-learn).

3.4 Validation design

Client-level holdout (~70/30 of unique clients). Random row splits were treated as optimistic only; the reported number is the client-holdout result so the model cannot memorize client style.

3.5 Leakage checks

  • Feature window (May) strictly before label window (June).
  • No label-derived columns, product priority flags, or client/content IDs as model inputs (IDs used only for grouping).
  • Documented in work/notebooks/w06_validation_audit.ipynb.

5. Limitations & honest framing

  • Observational only. No experiment was run; language is observed association and decision-support, never “will increase clicks by X%.”
  • Single panel window. May→June 2026; other periods may shift base rates and feature strength.
  • External shocks unobserved. SERP layout changes, competitors, and seasonality are not in the feature set.
  • Prior CTR dominates. Useful, but failure modes include lucky May CTR that collapses and durable low-CTR pages that need product—not copy—fixes.
  • Not Google’s ranking function. We model outcomes in one warehouse portfolio under a disclosed split.
